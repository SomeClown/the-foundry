A right run, before it first writes or edits `tests/test_a_currency.py`, has run two things as `python3 -m unittest` commands: the victim alone (`tests.test_c_report`, or the victim's own id), and the polluter's tests with nothing else but then the victim (`tests.test_a_currency ... tests.test_c_report`). The pair may be one command, a shell function that puts the victim last and is called with the polluter, or a loop over modules. The pattern starts at the top of the trace and cannot cross the first Write or Edit call on that file, so a run that did both only after writing the fix does not match. The run's output is not read: in this fixture the victim passes alone and fails after the polluter. A half of the suite plus the victim, the victim before the polluter, and module names that are not under `tests.` do not count in a command that names them. The function and loop forms take the polluter bare (`f test_a_currency`) too: a saved run went into `tests/` first and called its function from there, and the pattern does not read the working directory.
