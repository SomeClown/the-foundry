## 1. Goal and Approach

When this is done, `investigate` has no stop at any size. A sweep above the part size is read in parts. Each report is whole for the areas it read. Each opens with a `SWEEP IN PARTS` block that is the whole next brief. The session sends that brief back with `CONTINUE SWEEP` until a report says `0 areas not read`. Every report ends with `INVESTIGATE REPORT ENDS`.

The order matters. A fixture big enough for three parts comes first. Then come the measuring tools. Then the measurement of what reaches a caller, using today's definition at five or six report sizes in a live headless session and in the eval harness. That measurement sets the part size, or stops for the owner. Only after that does the agent wording get written with its tokens pinned. Then comes a proof that a session holding only the reports carries the sweep to the end. Last, the regular `investigate` checks and the docs.

Two approach choices carried weight:

- **Area commands.** Every area is rebuilt by one form: an `awk` filter over a single sorted listing. The listing is `git -c core.quotepath=off ls-files`, or the bounded `find` outside git. Git pathspecs would also work (yours were checked), but they need a second form outside git, and `:(glob)` reads `[`, `*` and `?` in folder names as patterns. `index()` in awk matches literally, and the same exactly-once check works in both places.
- **Grading the loop.** The loop proof is scored by a script over the saved part files, not by per-fact graders. A run with several parts can't echo every report in its last message, and grading the trace would count a reader's raw file read as finding the fact.

### Task 4: `check_parts.py`, the loop's scorer

**What to do.** Write `evals-expensive/check_parts.py`, standard library. It is called as `--key KEY --repo FIXTURE_DIR --parts DIR [--min-parts N]` and reads `DIR/part-1.md`, `part-2.md` and so on, in number order.

It runs these checks and prints one line per failure:

1. **Count.** At least `--min-parts` part files.
2. **Shape of each part.**
   - `SWEEP IN PARTS: <n> areas not read` is line 1, or line 2 under `NOT A PER-FILE READ`. A flag line is reported as a failure.
   - The block follows the Task 5 template exactly, up to `END OF BLOCK`.
   - The last non-blank line is `INVESTIGATE REPORT ENDS`.
3. **Order.**
   - The `n` values fall from part to part, and the last part says `0` with no area lines.
   - Each later part's block areas are a strict suffix of the earlier part's, matched as line text.
   - Each later part's `Areas read:` lines are exactly the prefix that was dropped.
4. **Notation.** Parse every area line as `- <name>: <definition> (<n> files)`. A definition is pieces joined by ` + `. A piece is `` `dir/` ``, `` `dir/` (direct) `` or `(root)`, optionally followed by ` except `` `dir/sub/` `` and/or ` from `` `first` `` to `` `last` ``. Rebuild each area in Python over the fixture's `./bin/git -c core.quotepath=off ls-files`, comparing paths as UTF-8 bytes. Each rebuilt count must equal the stated count.
5. **Exactly once.** The union of every part's `Areas read:` areas equals tracked files minus `layout.skipped_whole`, with each file in exactly one area.
6. **Coverage.**
