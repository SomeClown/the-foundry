## 1. Goal and Approach

When this is done, a lead is its own agent, `agents/area-lead.md`. It is on Sonnet, holds `Read`, `Glob`, `Grep`, `Bash` and `Agent`, and starts only `file-reader`. `investigate` dispatches it as `the-foundry:area-lead` (then the bare name `area-lead`) with the same `AREA LEAD` brief as today. It holds no lead-only text, and it answers an `AREA LEAD` brief with a fixed two-line reply. The rules both files need are copied word for word, and a table-driven test holds each copy equal to the one in `investigate`.

The move goes first, in two commits that change only who reads which text:
- **Task 2:** add the agent.
- **Task 3:** switch `investigate` over to it.

Those commits are measured against four "before" runs on 2.7.0's text. Then come Part 3's checklist fix and the architect's one sentence, each as its own task. Last comes the probe, which moves the sweep-in-parts text into a file loaded on demand. It is built on a branch that is never merged, measured, and written down.

The key trade-off is to split the move into "add" and "switch". The add commit alone leaves `investigate` unchanged. So any change in the after-runs comes from the switch, while every commit still leaves the gate green.
